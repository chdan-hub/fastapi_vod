Annotated란
타입 힌트에 추가 정보를 달아서, 검증/문서화/도구 활용에 쓰게 해주는 기능이다.
특히 Pydantic이나 FastAPI 같은 프레임워크에서 자주 활용한다.

ex)

‘’’
위 코드에서 UserId는 그냥 int이지만, "사용자 ID는 양수여야 함"이라는 설명이 붙은 것이다.
파이썬 인터프리터 자체는 이 설명을 무시하지만, 라이브러리(FastAPI, Pydantic 등) 가 이 정보를 읽어서 검증이나 문서 생성에 활용할 수 있다.

원래는 어떤 DB를 쓰는지 URL에 적을 필요 없다. 강의에서만 하는 것이며 실전에서는 db이름을 url에 넣지 않도록 한다.
edgedb_router = APIRouter(prefix="/v1/edgedb/meetings", tags=["Meeting"], redirect_slashes=False)

위 코드에서 v1/~/meetings 사이에 해당하는 edgedb, mysql을 말한다.

router 를 생성한 후, async 함수를 decorate 했다. 이 함수를 fastapi 에서는 path operation function 이라고 부른다.
클라이언트가 API 요청을 했을때 이 요청을 처리하는 함수가 path operation function 이다.

3.
파이단틱을 사용하는 이유
dto라는 폴더를 만들고 -> 그 안에 파이단틱 모델을 만들었는데
DTO: Data Transfer Object란
data 를 “전달”하기 위한 목적으로 생성한 객체를 의미합니다.
dto 는 오직 데이터를 “전달”만 해야 하며, 데이터를 수정, 추가, 삭제하면 안됩니다.
(수정 추가 삭제를 하는 순간부터 dto 는 dto 가 아니라 일반 오브젝트입니다.)

dto가 아닌 dict을 사용한다 하더라도 스웨거를 호출하면 작동은 하지만 fastapi 는 응답 json 에 어떤 key 가 들어가고,
그 key 의 value 는 어떤 타입인지 알 수가 없어집니다.

자세하게 설명하자면
(1) 직접 호출하지 않고는 그 안에 어떤 key 와 value 가 들어가는지 알 수가 없습니다.
-> 코드를 읽는 것으로는 동작을 이해할 수 없게 됩니다! (즉 읽을 수 없게 됩니다.)

(2) 개발도중에 실수로 key 를 누락하거나, 없는 key 를 추가해도 오류를 잡기가 쉽지 않습니다.
    dict 는 기본적으로 froze 되어있지 않기 때문에 생성 이후 중간에 값이 바뀌어도 이를 알 수가 없습니다.
->  한 번 생성된 객체 내부가 추후에 변경되는일이 잦다면 도무지 읽어서는 동작을 이해할 수가 없는 코드가 만들어집니다.
    결국 한 땀 한 땀 디버깅 해서 그 동작을 파악해 나가는 방법 말고는 없는데, 이 과정이 상당히 고통스럽습니다.

(3) 추가 설명
->  똑같은 응답이 오더라도 필수값인지 운이 좋아서 온지 알수가 없고(필수입지 옵셔널인지),
    옵셔널하게 오는 필드가 존재하더라도 옵셔널하게 필드가 전부 다 오는지 추가적인 필드가 있는지도 알 수 없다. dict은 frozen하지 않다.

정리
(1) 구현 보다 앞서 스펙을 동료들과 확정하고, 스펙 + 더미 response 먼저 만들어 배포하자.(내 동료와 프론트엔드 개발자를 위해서)
(2) timeit 을 사용해서 간단한 파이썬 코드조각을 성능테스트 할 수 있다.
(3) pydantic 으로 dto 를 생성할 수 있다.
(4) dict 대신 dto 를 사용하자!
(5) test.sh 를 실행한 후, 커밋 & 푸시 해 CI 가 정상 수행되는지 확인합니다.

고유한 식별자가 가져야 하는 특성들
    * 충분히 짧아야 하기 때문에 uuid4() 는 적합하지 않습니다. -> 각 언어별로 uuid는 라이브러리 형태로 존재한다. 버전 별로 알고리즘도 다르다
    * 고유함을 보장해야 하며
    * url 로 쓰여야 하기 때문에 특수문자가 들어간 것은 부적합하고, alpha numeric 이 좋습니다.

파이널은 재할당은 막지만 뮤텨블한 객채를 이뮤테이블로 만들진 않는다.

classvar은 클래스 변수를 의미한다. 클래스 변수란 클래스 레벨에서 정의되고 사용되는 변수를 의미한다.

Base62.encode() 를 호출하면 인자로 전달받은 int 가 고유한 문자열 식별자로 변환되도록 만들 것이다.

base64, base62 등등 base 계열 encoding 방식의 동작 원리
(1) 결과 값에 들어갈 수 있는 문자, 숫자를 미리 지정합니다. 이 값들의 개수가 64개면 base64 가 되고, 62개면 base62 가 됩니다.
(2) 앞으로 “결과 값에 들어갈 수 있는 문자, 숫자” 가 모두 들어있는 문자열을 base 라고 부르겠습니다.
(3) base 의 개수를 base_len 이라고 부르겠습니다.
(4) 하나의 정수를 인자로 받습니다.
(5) 정수를 base_len 으로 1번 나눈 후 몫과 나머지를 구합니다.
(6) base 의 “나머지” 번째 값을 결과에 추가합니다.
(7) 몫이 0이 될 때 까지 반복합니다.
(8) 결과를 문자열로 변환해 리턴합니다.

디버깅의 뜻
-> 디버깅(Debugging) 은 프로그램에서 발생하는 버그(bug, 오류) 를 찾아내고, 그 원인을 분석해서 고치는 과정을 말합니다.

디버깅 과정
(1) 문제 발견
* 프로그램이 실행 안 됨, 예상과 다른 결과, 에러 메시지 발생
(2) 원인 추적
* 로그 확인, 변수 값 확인, 코드 흐름 따라가기
(3) 해결 시도
* 코드를 고치거나, 잘못된 입력값을 수정하거나, 환경 설정 변경
(4) 재실행 후 검증
* 문제가 사라졌는지 확인

디버깅의 중요성
* 프로그래머의 자질은 코딩을 해서 제품을 만들 수 있는 능력이다
* 프로그래머가 갖춰야 할 가장 중요한 능력은 디버깅 스킬이다
* 디버깅을 잘한다는 것은 남의 코드를 잘 읽고 그 코드 속의 로직을 따질 수 있고 그 로직을 단계별로 나눌 수 있는 것이다
* 디버깅을 잘하면 남의 코드를 보는 것이 두렵지 않고 이 과정으로 배우는 것이 정말 많다
* 디버깅을 잘하는 프로그래머를 보면 엄청나게 성장할 것이란 것을 안다
* 정말 코딩을 잘하는 사람 중에 디버깅을 못하는 사람을 본 적이 없다. 디버깅을 잘하는 사람 중에 코딩을 못하는 사람을 본 적이 없다.
  디버깅을 못하는 사람 중에 코딩을 잘하는 사람은 (거의) 본 적이 없다. 디버깅을 못하는 사람 중에 설계를 잘하는 사람은 (거의) 본 적이 없다

Deterministic(결정적)
->  Base62 연산은 “결정적” 입니다.(deterministic) 결정적이라는 말은 같은 입력을 하면 항상 같은 결과가 나온다는 뜻입니다.
예시
->  덧셈, 곱셈 등은 같은 인자를 넣으면 항상 같은 결과가 나오므로 결정적. / random 뽑기 같은 연산은 실행할 때마다 결과가 다르므로 결정적이 아님.

정리
(1) base62 를 사용해서 uuid4 를 “짧게” 만들 수 있습니다.
(2) 중단점을 찍고 디버거를 사용하는 방법을 배웠습니다.
    * step over 로 한 줄 앞으로 실행, resume 으로 다음 중단점까지 실행합니다.
    * evaluate expression 을 사용하면 어떤 식도 실행하고 결과를 확인할 수 있습니다.
(3) 같은 인자를 넣으면 항상 같은 결과가 나오는 특성을 “결정적” 이라고 합니다.

Sqids이란
(1) 숫자에서 짧고 고유하며 무작위로 보이는 ID를 생성할 수 있는 작은 오픈 소스 라이브러리입니다.

(2) 링크 단축, 로깅을 위한 고유 이벤트 ID 생성, 웹 사이트의 제품/객체에 대한 ID 생성에 적합하며,
    한 번 디코딩되면 앱의 사용자 수를 드러낼 수 있기 때문에 민감한 데이터가 아닌 모든 데이터에 적합하지 않다

(3) 하나 또는 여러 개의 음수가 아닌 숫자를 하나의 ID로 인코딩할 수 있고, 숫자의 개수에는 제한이 없지만 숫자의 크기에는 제한이 있다

(4) 생성된 ID는 고유하며 기본 알파벳에는 대문자와 소문자가 모두 포함되어 있기 때문에 기본 ID는 대소문자를 구분합니다.

(5) 제약
    Sqids은(는) 음수를 인코딩할 수 없습니다.

    최소 알파벳 길이는 3자입니다.

    알파벳에는 다중바이트 문자가 포함될 수 없습니다.

    Sqids은(는) 특정 길이까지 ID를 생성할 수 없고, 최소한 특정 길이만큼은 생성합니다. 최소 길이 매개변수 범위는 0부터 255입니다.

    Sqids은(는) 알파벳 길이에서 하나를 뺀 만큼까지 ID를 재생성할 수 있습니다.
