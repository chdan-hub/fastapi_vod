1. DB 의 종류(Postgresql, MySQL, MongoDB 등)와 각 종류에 대한 특징을 이해하고 내 서비스에 적절한 데이터베이스를 선택할 수 있다.
2. sqlalchemy, tortoise ORM 등 요구사항에 적절한 ORM을 선택하여 활용할 수 있다.
3. aerich, alembic 등의 마이그레이션 도구를 활용할 수 있다.
4. FastAPI 의 Config 설정을 통해 데이터베이스 설정을 가져오고 적용할 수 있다.
5. ORM 을 활용하여 API를 작성할 수 있다.

------------------------------------------------------------------------------------------------

MySQL (관계형 DB, RDBMS)
    특징: 테이블 기반, SQL 사용, 트랜잭션·JOIN 지원한다.
    장점: 속도가 빠르고, 커뮤니티와 자료 풍부하다. 또한 웹 서비스에서 널리 사용한다.
    전형적인 웹 서비스(게시판, 예약, 쇼핑몰 등)에 적합하다.

PostgreSQL (관계형 DB, 고급 RDBMS)
    특징: MySQL보다 기능이 풍부하고, 정교한 쿼리·확장성 뛰어나다.
    장점: 데이터 무결성과 복잡한 쿼리에 강한 장점이 있다.
    금융, 복잡한 비즈니스 로직이 필요한 서비스에 적합하다.

MongoDB (비관계형 DB, NoSQL)
    특징: JSON 문서 형태로 데이터 저장하고, 스키마 자유롭다.
    장점: 빠른 개발 속도와 유연한 구조, 대용량 분산 처리에 강하다.
    SNS 피드, 로그 저장, 빠르게 변하는 데이터 구조에 적합하다.

EdgeDB
    특징: PostgreSQL 기반 + Graph 구조 쿼리 + 타입 시스템 제공
    장점: 직관적인 쿼리, 관계 탐색과 스키마 안정성 모두 확보
    복잡한 관계형 서비스, API 백엔드, SaaS에 적합하다


일반적인 웹 서비스 (블로그, 쇼핑몰, 예약 시스템) - MySQL
    -> 빠르고 안정적, 자료와 예제가 많아 배우기 쉬움

금융, 과학 연구, 데이터 분석 등 복잡한 쿼리와 확장성 필요한 경우 - PostgreSQL
	-> 고급 기능, 강력한 트랜잭션 처리, 확장성 우수

SNS, 채팅, 로그 저장, 실시간 데이터 처리 - MongoDB
    -> JSON 문서 기반, 스키마 유연, 빠른 개발 속도

복잡한 관계형 데이터 + 직관적인 쿼리 필요 (차세대 ORM 느낌) - EdgeDB
    -> PostgreSQL 기반, 직관적인 모델링, 현대적인 API 지원


MySQL/PostgreSQL = 전통적 RDBMS
MongoDB = 자유로운 문서형 DB
EdgeDB = PostgreSQL을 현대적으로 재해석한 신형 DB

Docker를 활용해 MySQL 서버를 로컬 및 CI 환경에서 실행하여 DB를 활용할 수 있었다.
lsof -i:3306 명령어를 써서 3306으로 쓰고 있는 것이 있는지 확인하고,
docker run --name mydb -e MYSQL_ROOT_PASSWORD=1234 -d -p 3306:3306 mysql:8을 이용해 연결했지만
3306 포트가 연결되지 않아 3307로 연결했더니 성공하여 3307 연결한 상태로 진행하였다.
연결 후 SELECT VERSION();을 날려 major이 8이상으로 시작한 것을 확인하였다.

Tortoise-ORM을 사용해 Python 코드로 DB 테이블과 컬럼 정의하고, Aerich를 활용해 모델 변경 시 DB 스키마를 자동 반영
tortoise-orm 은 사용 방법이 django orm 과 90% 흡사하다고 하는데 아직 장고도 배우지 않아서 두렵기만 하다.......

tortoise-orm에서의 connection은 어떤 driver 를 사용할지, database 의 host, port, user 등 접속 정보가 무엇인지 지정한다..
    - `connect_timeout: 5` 데이터베이스와 연결을 시도한 뒤, 5초 이내에 데이터베이스가 응답하지 않을 경우 기다리는 것을 멈춘 후 timeout error
       를 일으킵니다.
    - `maxsize: 30` 데이터베이스와 연결을 맺는일은 시간적 비용이 많이 드는 작업입니다.
       어짜피 데이터베이스와는 자주 소통하기 때문에 매 번 연결을 새로 맺는 것이 아니라 기존에 맺어두었던 연결을 재활용 함으로써 효율적으로 통신합니다.
       이를 “커넥션 풀” 이라고 하며, `maxsize` 는 커넥션 풀이 최대로 가지고 있을 수 있는 connection 의 수 입니다.
    - TORTOISE_APP_MODELS은 tortoise 의 규칙입니다. 설정 dict 에 어떤 tortoise model 들이 있는지 모두 등록해주어야 합니다.

ORM을 이용해 Meeting 생성, 조회, 수정, 삭제 기능 구현이 가능하고,
Python 코드에서 직접 SQL을 작성하지 않고도 데이터 조작 가능하다.

Pytest와 ORM을 활용해 DB 기능 테스트 코드 작성해
이를 통해 코드 변경 시 DB 연동 기능의 안정성을 자동으로 검증 가능.

Github Actions를 활용해 CI 환경에서도 MySQL과 ORM 기반 코드를 실행하도록 설정.
이를 통해 배포 전 자동 테스트, 데이터베이스 초기화 및 마이그레이션 적용 가능.

ORM 선택 기준
    동기(Synchronous) 환경, 복잡한 쿼리 필요
        -> SQLAlchemy
            이유: 강력한 쿼리 기능, 다양한 관계형 DB 지원, 복잡한 JOIN·서브쿼리 작성 용이
                장점: 강력한 쿼리, 고급 기능, DB 독립적
                    예시: 금융 서비스에서 다중 테이블 JOIN, 트랜잭션 처리

    비동기(Asynchronous) 환경, Python async 지원 필요
        -> Tortoise-ORM
            이유: 비동기 DB 연동 지원, 코드가 간결, FastAPI 등 async 프레임워크와 자연스럽게 연동
                장점: async 지원, 간결한 코드, 빠른 개발
                    예시: FastAPI 기반 예약 시스템에서 미팅 CRUD

    빠른 개발, 간단한 CRUD 위주
        -> Tortoise-ORM
            이유: 설정과 사용법이 단순, 모델 정의 후 바로 CRUD 사용 가능
                장점: 설정 단순, 바로 CRUD 가능
                    예시: 블로그 게시글, 댓글, 사용자 관리

    복잡한 트랜잭션, 정교한 데이터 처리
        -> SQLAlchemy
            이유: 트랜잭션 관리, 데이터 무결성, 고급 기능 제공
                장점: 트랜잭션 안정성, 정교한 데이터 제어
                    예시: 주문 결제 처리, 회계 데이터 관리

    테스트 및 마이그레이션 자동화 필요
        -> Tortoise-ORM + Aerich
            이유: 마이그레이션 도구 내장, 테스트 코드 작성과 연계 쉬움
                장점: 자동 마이그레이션, 테스트 코드와 자연스럽게 연계
                    예시: CI 환경에서 DB 마이그레이션 자동 적용

핵심
    SQLAlchemy → 복잡하고 정교한 쿼리, 동기 환경, 확장성이 중요한 프로젝트
    Tortoise-ORM → 비동기 환경, FastAPI 등과의 자연스러운 통합, 빠른 CRUD 개발, 테스트 및 마이그레이션 자동화

선택 원칙 요약
    개발 환경 기준
        비동기 → Tortoise-ORM
        동기 → SQLAlchemy

    기능/복잡도 기준
        단순 CRUD → Tortoise-ORM
        복잡 쿼리/트랜잭션 → SQLAlchemy

    운영/배포 기준
        테스트 자동화, CI/CD → Tortoise-ORM + Aerich
        고급 트랜잭션 관리 → SQLAlchemy

마이그레이션(Migration)은 데이터베이스 구조 변경을 관리하는 방법입니다.
    예: 테이블 추가, 컬럼 수정, 인덱스 생성 등.
        수동으로 SQL을 작성하면 오류가 생기거나 여러 환경에서 동기화가 어렵다. 그래서 마이그레이션 도구를 사용하면 안전하게 구조 변경을 관리할 수 있다.

Aerich은 Tortoise-ORM 전용 마이그레이션 도구
    역할 -> 모델 변경 감지 / 마이그레이션 파일 생성 / 데이터베이스 적용

    활용 예시
        aerich init -t config.TORTOISE_ORM  # 초기 설정
        aerich init-db                      # 초기 DB 생성
        aerich migrate                      # 모델 변경 감지 후 마이그레이션 파일 생성
        aerich upgrade                      # DB에 적용

    빠르게 모델 변경 사항을 DB에 반영하고 싶을 때 사용한다.

Alembic은 SQLAlchemy 전용 마이그레이션 도구, Aerich과 유사하지만 SQLAlchemy 환경에서 사용한다.
    활용 예시
        alembic init alembic                  # 초기 설정
        alembic revision --autogenerate -m "Add meeting table" # 마이그레이션 파일을 만들고 현재 DB 구조를 비교해서 자동으로 변경 사항을 감지하고 meeting 테이블 추가
        alembic upgrade head                  # DB 적용

    복잡한 스키마 관리와 버전 관리를 체계적으로 하고 싶을 때 사용한다.

실무에서는
    Tortoise-ORM + MySQL 프로젝트 상황일 때
        Aerich 사용
            why? Tortoise 전용, 자동화가 쉽고 Pytest, CI와 연동 용이

    SQLAlchemy + MySQL/PostgreSQL 상황일 때
        Alembic 사용
            why? SQLAlchemy 친화적, 버전 관리 기능 강력

    CI/CD 환경(Github Actions) 상황일 때
        둘 다 사용 가능
            why? 마이그레이션 명령어를 workflow에 추가하여 자동 DB 세팅 가능

                                                MySQL 서버를 Docker로 실행
                                                       │
                                                       ▼
                                                Tortoise-ORM 모델 생성 (예: Meeting 모델)
                                                       │
                                                       ▼
                                                Aerich 사용
                                                    aerich migrate → 변경 감지 → 마이그레이션 파일 생성
                                                    aerich upgrade → DB 반영
                                                       │
                                                       ▼
                                                Pytest + Tortoise-ORM 테스트 작성 후 실행
                                                       │
                                                       ▼
                                                Github Actions CI에서
                                                    MySQL 컨테이너 실행
                                                    Aerich migrate/upgrade 실행 → 테스트 자동화

Config 설정
    애플리케이션에서 공통으로 사용하는 설정값들을 한 곳에 모아 관리하는 방식입니다. (ex. 데이터베이스 주소, 포트, 사용자 이름, 비밀번호 등.)
        장점
            장점:
                코드 중복 방지
                환경(개발/테스트/운영)에 따라 다른 설정 적용 가능
                안전하게 관리 가능 (예: 비밀번호를 코드에 직접 쓰지 않음)

Config 클래스 작성
    from pydantic import BaseSettings

    class Settings(BaseSettings):
        MYSQL_USER: str
        MYSQL_PASSWORD: str
        MYSQL_HOST: str
        MYSQL_PORT: int
        MYSQL_DB: str

        class Config:
            env_file = ".env"  # 환경 변수 파일

환경 변수(.env) 예시
    MYSQL_USER=root
    MYSQL_PASSWORD=1234
    MYSQL_HOST=localhost
    MYSQL_PORT=3307
    MYSQL_DB=meeting_db

FastAPI에서 Config 불러오기
    from fastapi import FastAPI
    from config import Settings

    settings = Settings()
    app = FastAPI()

    # 데이터베이스 연결 문자열 구성
    DB_URL = f"mysql://{settings.MYSQL_USER}:{settings.MYSQL_PASSWORD}@{settings.MYSQL_HOST}:{settings.MYSQL_PORT}/{settings.MYSQL_DB}"

모델 정의
    # app/models.py
    from tortoise.models import Model
    from tortoise import fields

    class Meeting(Model):
        id = fields.IntField(pk=True)
        title = fields.CharField(max_length=255)
        start_time = fields.DatetimeField()
        end_time = fields.DatetimeField()

API 엔드포인트 구현
    # main.py
    from fastapi import FastAPI
    from app.models import Meeting
    from pydantic import BaseModel
    from datetime import datetime

    app = FastAPI()

    # Pydantic 모델: API 요청 본문(body)의 데이터 유효성 검사를 위해 사용
    class MeetingIn(BaseModel):
        title: str
        start_time: datetime
        end_time: datetime

    @app.post("/meetings/")
    async def create_meeting(meeting: MeetingIn):
        # ORM 모델(Meeting)을 사용하여 데이터베이스에 새로운 meeting 객체 생성
        new_meeting = await Meeting.create(
            title=meeting.title,
            start_time=meeting.start_time,
            end_time=meeting.end_time
        )
        return {"message": "Meeting created successfully", "meeting_id": new_meeting.id}

ORM 활용하면
    가독성 및 유지보수성: SQL 쿼리를 몰라도 데이터베이스를 조작할 수 있어 코드가 더 읽기 쉽고, 나중에 수정하기 편리합니다.
    데이터베이스 독립성: ORM을 사용하면 데이터베이스 종류(MySQL, PostgreSQL 등)를 바꿔도 대부분의 코드를 그대로 사용할 수 있습니다.
    보안: ORM은 자동으로 안전한 쿼리를 생성하기 때문에 SQL 인젝션 공격과 같은 보안 취약점을 방지하는 데 도움을 줍니다.
